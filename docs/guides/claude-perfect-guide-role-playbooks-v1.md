# Claude Perfect Guide
## Role-Based Playbooks v1

# 1. 개발자 플레이북

## Claude를 어디에 가장 많이 써야 하나
개발자에게 Claude의 가장 큰 가치는 “코드 잘 써주는 AI”보다 **코드 작업 전체를 덜 끊기게 만드는 것**에 있다.

## 가장 잘 맞는 작업
- 버그 재현과 원인 가설 정리
- 작은 범위의 안전한 수정
- 테스트 작성
- 리팩터링 계획 수립
- 레거시 코드베이스 온보딩
- PR 리뷰 초안
- 변경 사항 handoff 문서화

## 좋은 시작 문장
- 이 버그의 재현 경로를 먼저 정리하고, 관련 파일만 좁혀줘.
- 수정 전에 원인 가설 2개와 가장 가능성 높은 원인을 먼저 말해줘.
- 구현보다 먼저 테스트 관점에서 어떤 회귀가 생길지 봐줘.
- 관련 없는 파일은 건드리지 말고, 바뀐 파일과 이유를 함께 남겨줘.

## 개발자가 자주 하는 실수
- 저장소 전체를 한 번에 읽힘
- 원인 분석 없이 바로 수정부터 시킴
- 테스트 없는 결과를 곧바로 믿음
- 큰 리팩터링을 한 세션에 다 끝내려 함

## 운영 팁
- 큰 수정일수록 탐색/계획/실행/검증을 분리하라
- 검증 가능한 작업부터 맡겨라
- 끝날 때는 항상 “무엇이 바뀌었고 무엇이 남았는가”를 남겨라

# 2. PM / 기획자 플레이북

## Claude를 어디에 가장 많이 써야 하나
PM에게 Claude는 아이디어 생성기보다 **배경을 유지하면서 문서를 빠르게 구조화하는 파트너**에 가깝다.

## 가장 잘 맞는 작업
- 회의록 정리
- PRD 초안 작성
- 요구사항 비교표 생성
- 사용자 피드백 묶음 정리
- 기능 우선순위 논리 정리
- 경쟁 서비스 변화 브리프

## 좋은 시작 문장
- 이 회의 메모를 읽고 결정사항, 미결사항, 액션 아이템으로 나눠줘.
- 이 기능 요청을 사용자 문제, 비즈니스 가치, 구현 리스크 기준으로 정리해줘.
- 이 PRD 초안을 더 짧고 명확하게 다듬되, 애매한 요구사항은 따로 표시해줘.
- 기능 비교를 하되, “무엇이 더 좋아 보이는가”보다 “어떤 상황에 맞는가”를 중심으로 정리해줘.

## PM이 자주 하는 실수
- 배경 설명 없이 “PRD 써줘”부터 던짐
- 초안을 받자마자 확정본처럼 취급함
- 회의 메모와 결정 문서를 분리하지 않음
- 구조 없는 긴 문장을 계속 누적함

## 운영 팁
- Projects나 배경 문서에 공통 맥락을 쌓아라
- 템플릿을 따로 두면 문서 품질이 흔들리지 않는다
- Claude에게 ‘좋은 문장’을 맡기기보다 ‘좋은 구조’를 먼저 맡겨라

# 3. 마케터 플레이북

## Claude를 어디에 가장 많이 써야 하나
마케터에게 Claude는 카피 생성기보다 **자료를 압축하고 메시지를 날카롭게 만드는 편집 파트너**에 더 가깝다.

## 가장 잘 맞는 작업
- 캠페인 브리프 초안
- 경쟁사 카피 비교
- 랜딩페이지 메시지 구조화
- 광고 훅 정리
- 긴 글의 톤 보정
- 고객 인사이트 메모 정리

## 좋은 시작 문장
- 이 카피를 더 짧고 세게 만들되, 과장 없이 신뢰감 있게 다듬어줘.
- 이 세 가지 메시지 중 전환 가능성이 높은 축을 비교해줘.
- 경쟁사 표현을 그대로 따라하지 말고, 차별화 포인트만 추출해줘.
- 고객이 이해하기 어려운 표현은 쉬운 문장으로 바꿔줘.

## 마케터가 자주 하는 실수
- 톤 기준 없이 “더 세련되게”라고만 요청함
- 예시 없이 브랜드 톤을 추상적으로 설명함
- 조사 자료, 초안, 최종 카피를 한데 섞음
- 더 길게 쓰는 걸 더 좋은 카피라고 착각함

## 운영 팁
- brand voice 파일과 금지 표현 리스트를 따로 둬라
- 카피는 생성보다 비교가 중요하다
- 좋은/나쁜 예시를 함께 쌓아두면 결과가 빨리 안정된다

# 4. 1인 창업가 플레이북

## Claude를 어디에 가장 많이 써야 하나
1인 창업가에게 Claude는 보조 도구가 아니라 **생각, 문서, 구현 사이를 연결하는 멀티툴**에 가깝다.

## 가장 잘 맞는 작업
- 아이디어 정리
- 시장 브리프 요약
- 제품 카피 초안
- 사용자 피드백 정리
- MVP 수정 지원
- 운영 문서 초안

## 좋은 시작 문장
- 이 시장 메모를 읽고 지금 당장 중요한 변화만 골라줘.
- 이 랜딩페이지 메시지를 더 명확하게 만들고, 고객이 헷갈릴 표현은 표시해줘.
- 이 피드백을 읽고 반복되는 문제를 묶어서 정리해줘.
- 이 기능은 정말 지금 만들어야 하는지, 가치/복잡도 기준으로 따져줘.

## 1인 창업가가 자주 하는 실수
- 한 세션에서 전략, 카피, 코드, 운영 문서를 다 처리하려 함
- 생각 정리와 실제 실행을 분리하지 않음
- Claude 결과를 바로 확정안처럼 믿음
- 좋은 템플릿 없이 매번 0부터 시작함

## 운영 팁
- 생각 정리 / 문서 / 구현 세션을 나눠라
- 반복 업무는 템플릿화하라
- 지금 중요한 것과 나중에 해도 되는 것을 Claude에게 같이 구분시켜라

# 5. 운영 / 리서치 담당자 플레이북

## Claude를 어디에 가장 많이 써야 하나
운영/리서치 담당자에게 Claude는 검색 도구가 아니라 **자료를 읽고 구조화해서 의사결정 가능한 결과물로 바꾸는 도구**에 가깝다.

## 가장 잘 맞는 작업
- 주간 브리프
- 시장 조사 요약
- 커뮤니티 반응 정리
- 긴 문서 압축
- 이슈 분류
- FAQ 초안 생성

## 좋은 시작 문장
- 이 자료를 읽고 사실, 해석, 제안으로 나눠줘.
- 지난주와 비교해 새로 바뀐 점만 정리해줘.
- 출처와 날짜를 반드시 붙여서 요약해줘.
- 행동 제안은 3개 이하로만 정리해줘.

## 운영/리서치 담당자가 자주 하는 실수
- 출처 없이 요약만 받음
- 사실과 해석을 섞어버림
- 너무 많은 링크를 한 번에 넣음
- 읽기 작업과 보고용 정리를 구분하지 않음

## 운영 팁
- 출처, 날짜, 비교 기준은 항상 붙여라
- 원자료 폴더와 결과물 폴더를 분리하라
- 먼저 읽고, 그다음 정리하고, 마지막에 추천하게 하라

# 6. 공통 치트시트

## 모든 역할에 공통으로 먹히는 문장
- 먼저 범위를 좁혀줘.
- 관련 없는 부분은 건드리지 마.
- 결과보다 이유를 먼저 설명해줘.
- 초안과 확정안을 구분해줘.
- 바뀐 점과 남은 위험을 같이 적어줘.
- 출처와 검증 기준을 붙여줘.
- 사람이 다시 봐야 할 부분은 표시해줘.

## 모든 역할에 공통으로 피해야 할 문장
- 알아서 다 해줘.
- 다 고쳐줘.
- 더 좋아 보이게 해줘.
- 우리 스타일로 맞춰줘.
- 그냥 완벽하게 해줘.

## 한 줄 결론

직무가 달라도 원리는 같다.
Claude를 잘 쓰는 사람은 더 멋지게 요청하는 사람이 아니라, **작업의 범위, 기준, 검수선을 먼저 정하는 사람**이다.
