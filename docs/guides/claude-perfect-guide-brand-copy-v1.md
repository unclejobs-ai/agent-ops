# 메인 카피 후보

- 잘 쓰면 에이전트, 못 쓰면 비싼 챗봇
- Claude는 답하는 도구가 아니라 일하는 시스템에 가깝다
- 좋은 프롬프트보다 좋은 작업장이 먼저다
- 긴 설명보다 선명한 경계가 결과를 바꾼다
- AI의 품질은 모델보다 운영 습관에서 무너진다
- 자동화는 사람을 없애는 기술이 아니다
- 강한 에이전트의 문제는 대답이 아니라 권한이다
- 컨텍스트 관리가 실력이다
- 처음부터 큰일 맡기지 마라. 작고 되돌리기 쉬운 일부터 맡겨라
- Claude를 잘 쓰는 사람은 말을 잘하는 사람이 아니라 작업을 잘 쪼개는 사람이다

# 챕터 오프너용 문장

## 작업면
- 같은 Claude라도 앉혀 놓는 자리가 다르면 결과가 달라진다
- 질문할 땐 Chat, 맡길 땐 구조가 필요하다
- 작업대가 틀리면 기대도 빗나간다

## 요청
- 좋은 요청은 길어서 좋은 게 아니다. 경계가 있어서 좋다
- 범위를 안 정하고 맡기면 결과는 대개 넓고 흐려진다
- 좋은 요청은 Claude를 더 똑똑하게 만들지 않는다. 덜 흔들리게 만들 뿐이다

## Claude Code
- Claude Code의 핵심은 답변이 아니라 루프다
- 탐색 없이 고치면, 맞아 보여도 불안하다
- 검증 없는 결과는 초안일 뿐이다

## 컨텍스트
- 뭘 더 넣을지보다 뭘 빼야 덜 흐려질지가 더 중요하다
- 컨텍스트는 기억이 아니라 작업 반경이다
- 다 읽힌다고 다 잘하는 건 아니다

## 자동화 / 보안
- 맡길 수 있다고 해서 다 맡기면 안 된다
- 자동화의 핵심은 사람을 없애는 게 아니라, 사람이 꼭 봐야 할 지점을 줄이는 데 있다
- 비개발 업무라고 덜 위험한 건 아니다

## 마무리
- Claude를 설명하는 문서는 많다. Claude와 일하는 방식을 설계하는 문서는 드물다
- 잘 쓰는 사람은 기능을 많이 아는 사람이 아니라 기준을 먼저 세우는 사람이다
