# Claude Book Outline v1

가제: **잘 쓰면 에이전트, 못 쓰면 비싼 챗봇**
부제: Claude Code, Cowork, Projects, Chat를 관통하는 실전 사용법과 작업 철학

---

## 책의 방향

이 책은 기능 설명서가 아니다.
또, 페이지를 펼치자마자 바로 복붙하는 가이드북도 아니다.

이 책은 Claude를 둘러싼 도구와 작업 방식이 왜 바뀌고 있는지,
사람들이 왜 같은 모델을 쓰고도 전혀 다른 결과를 얻는지,
그리고 Claude를 어떻게 이해해야 실제로 일을 맡길 수 있는지 설명하는 책이다.

핵심은 세 가지다.

1. Claude를 단순한 채팅 도구로 보지 않게 만든다.
2. Chat, Projects, Cowork, Claude Code를 하나의 흐름으로 이해하게 만든다.
3. 좋은 사용법뿐 아니라 실패하는 방식과 오해까지 함께 보여준다.

---

## 목차 초안

### 서문. 왜 어떤 사람은 Claude로 일하고, 어떤 사람은 답만 받는가
- 이 책을 왜 지금 쓰는가
- 모델 비교보다 작업 구조가 중요해진 이유
- 질문창에서 작업장으로 넘어가는 순간

### 1장. Claude는 왜 이제 챗봇으로만 보면 안 되는가
- 답변 도구에서 작업 도구로 넘어온 변화
- 같은 모델인데 왜 결과가 달라지는가
- Chat, Projects, Cowork, Claude Code를 하나로 봐야 하는 이유

### 2장. 작업면이 다르면 사고방식도 달라진다
- Chat은 무엇에 강한가
- Projects는 왜 과소평가되는가
- Cowork는 왜 단순한 문서 도구가 아닌가
- Claude Code는 왜 터미널 챗봇이 아닌가

### 3장. 좋은 결과는 좋은 프롬프트보다 좋은 작업 구조에서 나온다
- 범위, 금지선, 출력 형식, 검증 기준
- 좋은 요청과 나쁜 요청의 차이
- 왜 사람들은 자꾸 너무 넓게 맡기는가

### 4장. Claude Code를 제대로 쓰는 사람은 무엇이 다른가
- 탐색, 계획, 실행, 검증
- 왜 검증 없는 결과는 초안에 불과한가
- 코드 생성보다 더 중요한 것

### 5장. 컨텍스트 관리가 실력이다
- 길다고 좋은 게 아닌 이유
- 상시 규칙과 임시 지시를 나누는 법
- CLAUDE.md, Skill, Subagent, Hook, MCP를 역할로 이해하기

### 6장. 자동화의 약속과 착각
- 자동화는 사람을 없애는 기술이 아니다
- 무엇을 맡기고 무엇을 멈춰야 하는가
- 보안과 권한이 왜 핵심이 되는가

### 7장. 사람들은 어디서 실패하는가
- 너무 넓게 맡길 때
- 한 세션에 너무 많은 일을 섞을 때
- 검증 없이 결과를 믿을 때
- 비개발 업무를 안전하다고 착각할 때

### 8장. 역할이 달라지면 Claude의 쓰임도 달라진다
- 개발자
- PM
- 마케터
- 1인 창업가
- 운영·리서치 담당자

### 9장. Claude를 둘러싼 비교는 왜 자꾸 엇나가는가
- Claude Code vs Chat형 AI
- Claude Code vs IDE 보조도구
- Claude Code vs Cowork
- 기능 비교보다 운영 철학 비교가 중요한 이유

### 10장. 결국 중요한 것은 기준이다
- 기능을 많이 아는 사람보다 기준을 먼저 세우는 사람이 유리하다
- 작은 성공을 반복해 작업 구조를 키우는 법
- Claude를 잘 쓴다는 것의 진짜 의미

### 맺음말. Claude를 설명하는 책이 아니라 Claude와 일하는 책
